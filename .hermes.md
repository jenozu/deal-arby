# Hermes Project Instructions — Deal Arby

## Mission
Build Deal Arby into a reliable online-arbitrage scanner that finds underpriced products, estimates conservative resale economics, ranks opportunities, persists history, and alerts only when configured thresholds are met.

## Source-of-truth order
1. Code, tests, and config on `main`
2. `master_plan.md`
3. `70-Project-State/current-state.md`
4. Architecture/strategy/decision notes
5. Inbox or older notes

## Before changing code
- Read `master_plan.md` and `70-Project-State/current-state.md`.
- Read only the relevant strategy/architecture/decision notes.
- Run the existing tests from `50-Code/`.
- Preserve public interfaces unless a roadmap task explicitly requires a change.

## Engineering rules
- Python package lives in `50-Code/dealfinder/`.
- Configuration lives in `50-Code/config/`.
- Tests live in `50-Code/tests/`.
- Prefer official APIs/feeds over brittle or prohibited scraping.
- Do not hardcode credentials, access tokens, cookies, or personal marketplace data.
- Keep valuation conservative; uncertainty should lower confidence or force manual review.
- Do not silently turn manual-review categories into automatic-buy recommendations.
- Add/adjust tests with every behavioral change.

## Documentation rules
After a material milestone:
- update `master_plan.md` checkboxes;
- update `70-Project-State/current-state.md`;
- create/update an ADR if an architectural choice changed;
- add durable research to the appropriate numbered folder, not to random root files.

## Immediate next milestone
Implement the eBay connector and valuation-comparables pipeline without weakening the existing calculator/evaluator/scoring gates.
